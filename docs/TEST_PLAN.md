# Test Plan

Automated (`npm test`, node:test, no DB needed) in `server/test/csv.test.js`:
- URL/domain normalization; funding normalization never invents funding
- CSV parsing: header mapping, unmapped columns, bad rows, missing name column
- Filter builder: regex escaping, AND logic
- `cleanPatch`: validation and field whitelist
- Research extractors: same-domain/generic emails only, job-like role links only

Manual/API smoke (run during the build against live Mongo): import + re-import (no duplicates), filters, status PATCH, invalid email rejected, stats, CSV export, research on example.com (honest empty result) and linear.app (careers page, email, roles with sources).

Import/export (`test/import.test.js` pure, `test/api.test.js` against a real MongoDB test DB): quoted commas/newlines/escaped quotes, Unicode, BOM, blanks, ragged rows, malformed/binary/non-UTF-8/empty files, 413 oversize, missing names, mapping validation, same-file-twice, in-file duplicates, similar names not merged, possible duplicates and per-row decisions, protected notes/status/dates/verified data, blank cells never erasing, dry run writes nothing, export filters and formula guard, export -> wipe -> re-import round trip, 3,000-row import.

Research (`research-safety`, `research-extract`, `research-run` need no database; `research-api` uses its own test DB). Local HTTP fixture servers are used, and the test fetcher can reach only those ports.
- Safety: invalid/unsupported URLs (schemes, credentials, ports, internal names, decimal/hex/IPv6/mapped IPs), blocked IP ranges incl. metadata, DNS answers that are private or mixed, DNS resolved once per request and connected to the validated address, redirects to internal/metadata/ftp/file/off-site/loops, timeouts (hang and slow-drip), size cap, non-HTML/compressed, no cookies/credentials, request budget, per-host rate limit, crawl-delay, connection refused.
- Extraction: link classification, role keywords (configurable, whole-word), emails (role-style, company domain only), funding leads (no invention), malformed/hostile HTML, regex-DoS guard.
- Runs: findings with per-finding sources, page/request limits, robots.txt (Disallow, Allow precedence, own-UA group, 404, 500, Disallow all), homepage failures (404/403/429/503/not HTML/timeout/connection/DNS/off-site redirect/private targets), error messages free of internals, not-found semantics.
- Service/API: async start, duplicate-run lock (409), stale lock and restart recovery, manual/verified value preservation and conflict handling, edited accept, funding never marked verified, reject/re-run behaviour, bulk decisions, batch limits, hand-edits clearing research provenance.

Application tracking (`applications.test.js` pure; `applications-api.test.js` with its own test DB): creation/editing and validation, all 49 status transitions with history, automatic applied/contact dates, multiple roles at one company with independent statuses and a furthest-status summary, duplicate protection (role, URL, concurrent double submit, rename into duplicate), follow-up due/overdue (list, stats, filter, finished applications excluded), activity history, company-level compatibility (0/1/many applications), notes surviving imports, imported tracking columns, migration (no invented dates, idempotent), applications CSV, persistence across a simulated restart.

Outreach (`outreach.test.js` pure, `outreach-api.test.js` with its own test DB): input validation, facts labelled by origin (funding/notes never used), missing-context reporting for every purpose, template content and discipline for every purpose (no invented numbers/claims, passes its own validator, word limit), output validation rejecting invented numbers/funding/attachments/links/emails, provider call shape and error mapping via the official SDK error classes, key handling, AI fallback on invalid/malformed/failing replies without leaking secrets, hostile company text, AI rate limit, draft save/edit/validation/cap, manual "sent" (date, application update, never backwards, read-only once sent), cascade delete, persistence across restart, and a guard that no email-sending code exists. **Not covered: a live AI call.**

Security and data quality (`security.test.js` needs no database; `security-api.test.js` uses its own test DB; research concurrency in `research-api.test.js`): host/origin/CORS guards, response headers, JSON 404, malformed/oversized bodies, error sanitising (stack/paths/connection strings), per-endpoint rate limits, upload limits, secret scanning and connection-string masking, operator-injection bodies on every write endpoint (no change, no leak), query-string operators and regex-DoS text, `Object.prototype` lookups (`sort=constructor`, CSV column `constructor`), length/type limits, import lock and concurrent imports, honest partial-import report, hostile CSV headers, formula guard incl. headers, double-submit drafts, integrity check/repair that never deletes, research concurrency cap. Each protection was mutation-checked.

Real-browser check (`npm run ui-check`, optional, needs Edge or Chrome, internet and a throwaway database): drives the actual UI through the empty state, clean and messy imports (mapping, dry-run review, duplicate decisions, error rows), search/filters/quick chips, applications (two roles, duplicate refusal, overdue banner, status change and history, summary row), outreach (missing-info prompt, draft contents, facts, save, "I sent this"), research failure + retry and a live success (sources, accept, safe links), export and reload persistence, 390px mobile layouts, the loading state and the API-unreachable error. It also fails on any browser console error. 45 checks. It found and led to fixing a nested-form bug and an application date rule that rejected moving an overdue application forward.

Also verified by hand during demo preparation: clean install from a fresh copy (`npm run setup`, tests, build, start), MongoDB stopped and restarted while the API runs (503 within 0.2 s, recovery in about 6 s), start-up failure message, and an export → wipe → re-import round trip of 17 companies (identical apart from a trailing slash on one source URL).

Not covered yet: React component tests (the browser check above covers the main flows), research route tests beyond the service/API tests, a live AI call.
